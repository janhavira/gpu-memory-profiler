Findings, kernel by kernel

matmul_naive global memory

No shared-memory tiling: every element of A and B is re-read from global memory once per output element — O(n) redundant traffic on a 4096×4096 matrix.

before
for (int k = 0; k < n; ++k)
  sum += A[row*n+k]
       * B[k*n+col];
after
__shared__ float As[T][T], Bs[T][T];
// load one tile per block,
// __syncthreads(), accumulate
// from shared mem, advance k
transpose_naive global memory

The write index strides by n floats per thread — a warp touches up to 32 separate cache lines instead of one contiguous 128-byte line.

before
out[x*n + y] = in[y*n + x];
after
tile[ty][tx] = in[y*n+x];   // coalesced read
__syncthreads();
out[oy*n+ox] = tile[tx][ty]; // coalesced write
reduce_columns shared / L1

Tile declared [TILE][TILE] with TILE = 32: the row stride equals the bank count, so repeated-iteration accesses to the same column collide on one bank.

before
__shared__ float tile[TILE][TILE];
after
__shared__ float tile[TILE][TILE + 1];
// +1 shifts each row's start bank
apply_lut L2 / read-only cache

The read-only lookup table is loaded through a plain pointer, so the compiler can't route it through the dedicated read-only data cache without proof that out doesn't alias it.

before
out[i] = lut[idx] * data[i];
after
// params: const T* __restrict__
out[i] = __ldg(&lut[idx])
       * __ldg(&data[i]);
poly_eval_heavy registers

A 64-element per-thread array is likely too large to stay resident in registers — the overflow spills into local memory, which is physically carved out of global memory.

before
float coeffs[64];
for (c=0;c<64;++c) coeffs[c]=...;
for (c=0;c<64;++c)
  acc += coeffs[c]*coeffs[63-c];
after
for (c=0;c<32;++c){
  float a=..., b=...;   // fused,
  acc += a*b;           // no array
}
